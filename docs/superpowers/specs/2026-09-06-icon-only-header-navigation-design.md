# Иконки в верхней навигации

## Цель

Сделать desktop-версию верхнего меню компактнее: заменить текстовые пункты навигации и системные действия на иконки, сохранив понятное активное состояние и полную доступность. Логотип и строка поиска остаются без изменений.

## Desktop-навигация

Каждый пункт `navLinks` получает имя Material Symbol:

- Today — `today`
- Recent — `history`
- Favorites — `star`
- Search — `saved_search`
- Views — `view_list`
- Tasks — `task_alt`
- Attachments — `attach_file`
- Discovery — `explore`
- Graph — `hub`

Неактивный пункт отображает только иконку в квадратной кнопке. Активный пункт расширяется и показывает иконку с короткой локализованной подписью. Быстрый захват сохраняет существующую акцентную кнопку `add`.

Профиль, администрирование, тема и выход уже используют иконки. Переключатель языка меняется с видимого `EN/RU` на Material Symbol `language`; текущий язык остаётся в локализованном `title` и `aria-label`.

## Mobile-навигация

В выпадающем мобильном меню каждый пункт показывает иконку и текстовую подпись постоянно. Это сохраняет понятность меню на сенсорном экране. Системные действия в мобильной верхней строке остаются иконками, включая новый переключатель языка.

## Визуальное поведение

- Все desktop-кнопки имеют одинаковую высоту и базовую ширину.
- Активная кнопка использует существующие primary border/background и расширяется только на ширину подписи.
- Hover и keyboard focus остаются визуально различимыми.
- Иконки выравниваются по центру; между иконкой и активной подписью используется небольшой фиксированный отступ.
- Смысловые разделители не добавляются: выбран вариант единой панели с активной подписью.

## Доступность

- Каждая icon-only ссылка получает локализованные `title` и `aria-label`.
- Иконка помечается `aria-hidden="true"`.
- Активная подпись остаётся обычным видимым текстом.
- Текущие router-link active states и keyboard navigation сохраняются.
- Переключатель языка сообщает текущий язык и действие через `title` и `aria-label`.

## Компоненты и данные

Изменения ограничены `AppHeader.vue`, его component-тестом и необходимыми строками i18n. Поле `icon` добавляется непосредственно в элементы `navLinks`; отдельный универсальный компонент для одной небольшой панели не вводится.

## Проверка

Component-тесты подтверждают:

1. каждый desktop-пункт содержит ожидаемую иконку и доступное имя;
2. текстовая подпись видна только у активного desktop-пункта;
3. мобильные пункты всегда содержат иконку и подпись;
4. переключатель языка больше не показывает `EN/RU` как основной контент, но сообщает текущий язык доступным именем;
5. существующие поиск и shortcut быстрого захвата продолжают работать.

После unit-тестов выполняются полный frontend test suite, lint и production build. Визуальная проверка проводится через локальный Kubernetes-контур.
